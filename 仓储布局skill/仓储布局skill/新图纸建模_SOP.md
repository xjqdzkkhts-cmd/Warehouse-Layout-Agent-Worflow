# 新图纸 → Blender 仓储场景 · 标准作业流程（SOP）

> 适用：拿到一份新的仓储或产线 DXF 规划图，要得到可调整、可对照、验收通过的 Blender 三维场景。
> 分工：**你**负责提供输入、回答问题、做最终判断；**AI agent**（已加载 skill `dxf-blender-layout`）负责识图、出清单、调用插件；**插件**（仓储布局工具）负责生成、底图、墙体和验收。

## 流程总览

```
0 一次性准备 → 1 准备输入 → 2 启动任务 → 3 AI 走查 → 4 你来确认
      → 5 生成设备 → 6 底图与墙体 → 7 验收 → 8 人工微调 → 9 交付归档
```

其中第 4 步和第 7 步是**必须由你把关**的两个节点，其余步骤主要由 AI 和插件完成。

---

## 0. 一次性准备（每台电脑只做一次）

| # | 事项 | 做法 | 完成标志 |
|---|---|---|---|
| 0.1 | Blender 4.2+ | 已装 4.4 | — |
| 0.2 | 安装插件 | 编辑 → 偏好设置 → 获取扩展 → ⌄ → 从磁盘安装 → `warehouse_layout-x.y.z.zip` | 3D 视图按 N，出现「仓储布局」面板 |
| 0.3 | 插件偏好 | 填**资产库 .blend** 路径；提升机默认高出 1.0m；类型关键词按资产命名调整 | — |
| 0.4 | Blender 工具连接 | 按所用客户端配置 Blender MCP 并启动服务，或使用可执行 Blender Python 的其他连接 | AI agent 能读到场景信息并执行 Blender Python |
| 0.5 | 安装 skill | 按所用 agent 的文档安装完整 `dxf-blender-layout/` 文件夹；不支持自动发现时，指定 `SKILL.md` 路径并要求读取引用文件 | AI agent 能读取技能、引用资料并运行脚本 |
| 0.6 | 资产库 | 设备模型都放在一个 .blend 里，并标记为资产集合；**命名要带类型关键词**，比如"…提升机""…货架""…护栏" | 验收报告能按类型正确计数 |

## 1. 准备输入（每个项目）

**1.1 建项目文件夹**（沿用这次的结构）：

```
<项目>/
├── 图纸输入/      ← DXF 放这里
├── 参考图/        ← 效果图、俯视参考图（可选，但强烈建议有）
└── 输出/          ← 场景、清单、配置都会写到这里
```

**1.2 图纸要求**
- 格式为 **DXF**。拿到 DWG 的话，在 CAD 里另存为 DXF（2018 或更早的版本都可以）。
- 外部参照要**绑定**后再导出，否则建筑墙体进不来。
- 文件大一点没关系，这次 140MB 的图纸也能正常处理。

**1.3 提前准备这些参数，能大幅减少来回沟通**

| 参数 | 例子 | 没有的话会怎样 |
|---|---|---|
| 立库总高或储位层数、层高 | 20m | AI 会停下来问，平面图里读不出来 |
| 堆垛机型号 | 单立柱 | 会问 |
| 托盘样式 | 蓝色塑料托盘 | 会问 |
| 各区墙高 | 立库区 22m，其余 6m | 先用 6m 占位，事后要改 |
| 要建哪一层 | 默认首层 | 默认只建 1F，贯通立库保留完整高度 |
| 参考图 | 1F 俯视效果图 | 块的含义拿不准时（比如这次的端部护栏）更容易误判 |

## 2. 启动任务

1. 打开 Blender，新建或打开一个**空场景**，启动 MCP 服务。
2. 在已配置文件访问、Python 执行和 Blender 工具连接的 AI agent 中发送任务，下面是模板，把参数替换成你的：

```
读取 <技能路径>/dxf-blender-layout/SKILL.md，按其中流程和引用资料，把 <项目>/图纸输入/xxx.dxf 转成 Blender 场景。
资产库：<路径>/设备模型库.blend；输出到 <项目>/输出/。
已知参数：立库总高 20m，单立柱堆垛机，蓝色塑料托盘，墙高 6m。
参考图：<项目>/参考图/1F俯视.png
```

## 3. AI 首次走查（AI agent 执行）

AI agent 会做这些事：
- 统计图纸，找出每层平面分别在哪；
- 识别设备块，解析动态块的原名；
- 排除图框外副本、别的楼层图层、标注类块；
- 定原点，写 `project-config.json`，里面包括底图区域和墙体图层。

**你会拿到（固定在 `输出/识图确认/` 里，这一轮不会建 .blend）：**

```
输出/识图确认/
├── 1F设备清单.csv        每个设备一行，带稳定编号、建议资产，最后有「用户确认」「用户备注」两列
├── 1F编号预览.png        按分组着色的平面图，拿不准的项用红字标出编号
├── 1F识图摘要.md         分组表、排除表、原点、需要注意的地方、编号问题清单
├── 1F待确认局部.png      可选：看不懂的块的局部截图，每格标编号和尺寸
├── project-config.json   项目配置，也是 AI 和插件之间的交接文件
├── placements.json       位置数据，供生成使用
└── _过程/                AI 的中间文件，不用看，可以删
```

你只需要看前三个（有第四个的话也看一下）。问题清单在对话里也会贴一遍，按编号回答就行。确认后 AI 会在原文件上更新，不会另存副本。

## 4. 你来确认（把关点 ①）

**逐项检查：**
- [ ] 打开 `编号预览.png`，和 DXF 或参考图对照，**整体布局是否一致**，有没有漏掉区域。
- [ ] 看**排除清单**：图框外副本、别的楼层图层、标注，确实都不该要吗？
- [ ] 回答问题清单：设备含义、代用资产、高度参数。
- [ ] 特别看一下**端部、角落的小块**。这次的 `单货位` 一开始被识别成托盘，实际是护栏。**有参考图的话一定要给 AI。**

**回复方式二选一：**
- 直接在对话里回答，例如"G11 是牙叉辊筒输送机，G15 不用管，托盘用蓝色塑料"；
- 或者在 CSV 的确认列里填好，把文件发回给 AI。

> 没确认的项目，AI 不会自己猜着生成，会一直留在待办里。

## 5. 生成设备（AI 调用插件）

你确认之后，AI agent 会依次完成：

1. 从资产库**链接**资产，不导入副本。
2. 用几何节点生成设备，每个可以独立调整的单元单独一个对象：

| 区域 | 形式 | 在 Blender 里怎么调 |
|---|---|---|
| 立库 | 每排一个 XYZ 阵列 | X 数量 = 货位数；Z 数量、Z 间距 = 竖向节数、节高 |
| 横梁货架 | 每个连续段一个 XYZ 阵列，同一排挂在同一个父级下 | 背靠背的两列是 Y=2；中间的缺口保留 |
| 地堆托盘 | 每个矩形一个阵列，同一区块挂在同一个父级下 | X、Y 数量 |
| 输送线 | 每条直线一个点位对象（多种设备混在一起） | 离地高度等 |
| 堆垛机、提升机 | 单独的对象 | 每条巷道 1 台堆垛机；提升机会自动对齐到货架顶加 1m |
| 巷道端护栏 | 点位对象 | 离地高度；护栏要罩住轨道端部 |

## 6. 底图与墙体（插件一键完成）

| 步骤 | 面板按钮 | MCP 调用 | 结果 |
|---|---|---|---|
| 6.1 导入平面底图 | 导入平面底图 → 选 `project-config.json`，「替换图纸」留空 | `wh.import_underlay` | `DXF底图` 集合，按图层分对象，放在模型下方；第一次约 40–50 秒，之后读缓存约 0.1 秒 |
| 6.2 挤出墙体 | 一键挤出墙体，填墙高 | `wh.build_walls` | `建筑_1F`：每个空间一个墙体对象，外加柱子 |
| 6.3 对照检查 | 对照模式 | `wh.compare_mode` | 顶视正交视图，模型半透明、底图着色；再点一次恢复原视图 |

提示：底图里不需要的图层（暖通、管线等），在大纲里点眼睛图标隐藏即可。想以后都不导入，就让 AI 把这些图层加进配置的排除列表。

## 7. 验收（把关点 ②）

**7.1 程序验收**：点「验收报告」，或者让 AI 执行 `wh.validate`。以下各项要**全部 PASS**：
- 提升机高于货架（高出 0.3–2.0m）
- 堆垛机顶约等于货架顶
- 堆垛机与货架无干涉
- 每巷道一台堆垛机
- 护栏罩住轨道端部

同时核对报告里**按资产的计数**和清单是否一致。

**7.2 视觉验收**（打开对照模式）：
- [ ] 全局顶视：模型和底图线整体重合。
- [ ] 放大 2–3 处典型区域（立库出入口、立库尾端、产线交叉口），看朝向和位置。
- [ ] 切到透视看高度：货架、堆垛机、提升机、墙之间的高低关系合理。
- [ ] **判断"有没有罩住、有没有对齐"时，看顶视正交图或数字，不要只看透视图**，透视有视差，容易误判。

## 8. 人工微调

| 想改什么 | 怎么改 |
|---|---|
| 某排货架加或减货位 | 选中该排，在「当前对象参数」里改 **X 数量** |
| 立库加层或改层高 | 改 **Z 数量**、**Z 间距** |
| 货架整体高度 | 改完之后点「提升机/堆垛机高度对齐」，提升机会跟着变 |
| 某个空间的墙高 | 选中 `墙体_空间NN`，改「高度」 |
| 挪动一整排或一个区块 | 选中父级空对象（`横梁货架_NN`、`地堆_区块NN`）整体移动 |
| 堆垛机停在巷道中间做展示 | 直接沿 X 方向拖动 |

**改完一定要重新点一次「验收报告」。**

## 9. 交付与归档

`输出/` 目录里应该有：
- [ ] `<项目>_1F布局.blend`：资产库用相对路径链接，**两个目录要保持现在的相对位置**，挪动的话一起挪。
- [ ] `识图确认/`：第 3 步那套文件（设备清单、编号预览、识图摘要、`project-config.json`、`placements.json`），已按你的确认更新过。`project-config.json` 里记着所有确认过的参数、假设和跳过的项目，以后改版要用。`_过程/` 可以删。
- [ ] 验收报告：Blender 文本块 `WH_验收报告`，或者导出成 JSON。
- [ ] 需要的话，备份上一个版本的 .blend。

## 10. 图纸改版时

1. **新图坐标没变**（设计院在原图上修改）：
   - 在「导入平面底图」里填「替换图纸」，选新 DXF，然后打开对照模式，看哪里对不上；
   - 让 AI 基于原来的清单做**差异核对**，只重新确认有变化的部分。
2. **坐标变了或重新排版**：从第 2 步重新开始走查。原来的 `project-config.json` 可以作为参考，已经确认过的参数不用再答一遍。

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| 面板里没有「仓储布局」 | 检查扩展有没有启用；按 N 打开侧边栏 |
| 底图里没有墙 | 可能是外部参照没绑定就导出了 DXF；或者配置里的区域太小，没把建筑包进来 |
| 两个房间被合成了一个空间 | 门洞处没有画门扇和门弧；可以接受，或者在 CAD 里补一条封口线 |
| 验收报告的计数不对 | 资产名里没有类型关键词，到插件偏好里调整「类型规则」 |
| 第一次导入底图很慢 | 正常，40–50 秒；之后读缓存 |
| AI 问了已经回答过的问题 | 提醒它读 `project-config.json`，已经确认的内容都记在里面 |

## 12. 经验回流（让下一次更顺）

项目做完后，花几分钟把新发现告诉 AI agent，比如"这类图纸的 XX 块其实是 YY"或者"以后墙高都按区域分开设"，让它写回 skill：
- **流程偏好、红线**：写进 `SKILL.md` 的关键约束；
- **识图经验**：写进 `references/warehouse-patterns.md`；
- **新的一键功能需求**：记进插件 PRD 的路线图。

每回流一次，下一份图纸的问答轮数和返工都会少一些。
