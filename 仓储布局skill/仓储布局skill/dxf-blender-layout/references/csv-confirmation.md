# 集中确认

第一轮对话（首次走查 + 集中确认）只产出下面这套文件，**不建 .blend、不改 Blender 场景**。

## 输出目录（固定结构）

```
<项目>/输出/识图确认/
├── 1F设备清单.csv        ① 给用户看、可编辑
├── 1F编号预览.png        ② 给用户看
├── 1F识图摘要.md         ③ 给用户看：分组、排除、原点、问题清单
├── 1F待确认局部.png      ④ 可选：只在有看不懂的块时出
├── project-config.json   ⑤ 交接给插件和后续步骤
├── placements.json       ⑥ 交接给生成步骤
└── _过程/                中间文件，用户不用看，可以删
```

规则：

- **楼层标签统一用 `1F`、`2F`、`B1`**，不用“一楼”“首层”。多个楼层就每层一套 ①–④、⑥，共用一个 ⑤。
- **顶层只放上表这些文件**。统计、文字、视图分布、初览渲染、`<楼层>_inserts.json`、候选插入、资产列表、子设备展开等中间结果一律放 `_过程/`，名字随意。
- 预览只出 PNG，不出 HTML 版。
- 插件导入底图时会在 `project-config.json` 旁边写 `.wh_underlay_*.npz` 缓存，这个是正常的，不用管。
- 用户确认后**原地更新**这几个文件，不另存 `_v2`、`_确认版` 副本。

## ① `<楼层>设备清单.csv`

UTF-8 BOM，Excel 可直接打开。每个插入一行，按分组、Y、X 排序。列名和顺序固定：

```
编号,分组,说明,建议资产,处理,DXF块,动态原名,图层,句柄,中心X_m,中心Y_m,旋转_deg,镜像X,镜像Y,长X_m,宽Y_m,用户确认,用户备注
```

- `编号`：稳定编号 `分组-序号`，例如 `G05-0012`。后续对话、验收都按它引用，生成后不重编。
- `分组`：设备用 `G01…`，排除项用 `X01…`（排除也要成行，方便用户核对）。
- `处理`：只能是 `生成`、`排除`、`待确认`。
- `镜像X/镜像Y`：1 或 -1。
- `用户确认`、`用户备注` 留空给用户填。

## ② `<楼层>编号预览.png`

用 `scripts/preview_numbered.py` 从 ① 直接生成，不要另写绘图代码：

```
python scripts/preview_numbered.py 1F设备清单.csv --out 1F编号预览.png \
    --title "1F 设备分组预览（单位 m，原点=DXF(x,y)mm）"
```

效果：按分组着色的矩形平面，每组第一个位置标粗体分组号，“待确认”项用红字标编号，右侧图例为“分组 说明”，“排除”项不画。标题写明单位和原点。脚本只读 `编号, 分组, 说明, 处理, 中心X_m, 中心Y_m, 长X_m, 宽Y_m` 这几列。

## ③ `<楼层>识图摘要.md`

固定四节，内容和对话里给用户的一致：

```markdown
# 1F 识图确认

状态：尚未生成 Blender 场景。<一句话：已确认什么、还缺什么>

## 分组
|分组|说明|数量|建议资产|处理|
|---|---|---:|---|---|
|G01|立库托盘货架排|28|横梁货架|生成|
|X01|图框外托盘线副本|137||排除|

## 坐标
原点：DXF (x, y, 0) mm；主图范围：(x0, x1, y0, y1) mm；单位换算 mm → m。

## 需要注意
<副本偏移、图层混入、组合块展开、数量对不上的地方，每条一句>

## 问题清单
1. G06 堆垛机用哪种？（单立柱 / 双立柱）
2. ……
```

问题只问会改变生成结果的，一次问完、编号，方便用户按号回答。

## ④ `<楼层>待确认局部.png`（可选）

只在有“待确认”的块时出：把这些块在 DXF 里的局部渲染拼成一张，每格标编号和尺寸。用 `dxf_inventory.py render --region` 渲染。

## ⑤ `project-config.json`

基于 `assets/project-config.json`，未知项保持 null。写好 `underlay` 段（底图区域、排除的图层、是否带文字）；墙体图层能认出来的话，把 `walls` 段也写好。

## ⑥ `placements.json`

所有非排除项，结构固定：

```json
{
  "origin_dxf": [x, y, 0],
  "units": "m",
  "status": "draft | confirmed",
  "placements": [
    {"id": "G01-0001", "group": "G01", "handle": "DDCED", "block": "*U6557", "dyn": null,
     "layer": "0", "cx": 46.75, "cy": 29.314, "rot": 0, "sx": 1, "sy": 1, "w": 91.75, "d": 1.2}
  ]
}
```

坐标已减去原点并换算成 m。`id` 和 ① 的 `编号` 一一对应。

## 本轮结束时的回复

在对话里列出 ①–⑥ 的路径（④ 没有就不列），然后贴出问题清单。不要把 `_过程/` 里的文件列给用户。

## 问题清单常见条目

- 立库和货架：储位层数、层高、总高（平面图没有时必问）；
- 堆垛机型号（每条巷道只生成一台，图纸两端各画一台时不再询问）；
- 没有对应资产的设备怎么处理（代用、简单几何体或不生成）；
- 看不懂的块：给出编号、尺寸和位置；
- 托盘样式；
- 已排除的内容是否同意排除，尤其是“图框外副本”和“别的楼层图层”。

## 接收校准

- 用户可能直接在对话里回答，不填 CSV，这样也算确认。把答案写回 ① 的 `用户确认` 列和 ⑤，⑥ 的 `status` 改为 `confirmed`，③ 的状态行和问题清单同步更新（标上答案）。
- 用户说“不用管”的分组，改为 `排除`，并在 ③ 里记录原因。
- 给了总高、没给层数时：按总高生成，同时在配置和交付说明里写明“层数为视觉近似”。
- 改了 ① 之后重跑 `preview_numbered.py` 刷新 ②。
