# 仓储布局工具 · 产品需求文档（PRD）

| 项 | 内容 |
|---|---|
| 产品 | 仓储布局工具（Blender 扩展，id `warehouse_layout`） |
| 当前版本 | 0.3.0 |
| 运行环境 | Blender 4.2+（已在 4.4.0 验证），macOS / Windows / Linux |
| 配套 | AI agent skill `dxf-blender-layout`（负责识图与确认） |

---

## 1. 背景

把 DXF 仓储规划图转成 Blender 三维布局，原来全靠 AI 边分析边写代码：
- 节点组、摆放、验证代码每次都要现写，占了这次对话大部分的 token；
- 同样的逻辑在不同阶段被反复重写（整区对象 → 按排按列 → XYZ 阵列），每一轮都要重写代码、重新核对；
- 结果难以复现，人离开 AI 就没法继续调整。

**目标：** 把确定性的执行和检查固化到插件里，AI 只负责识图语义和与人确认。

## 2. 目标与非目标

**目标**
1. 模型调用一行操作器，替代几十到上百行现写代码；只回读几行摘要。
2. 重复区域可编辑：按 X/Y/Z 分别调数量和间距，按排、列、线、空间独立调整。
3. 平面底图和模型永远对得上，人可以直接对照。
4. 行业规则自动检查：提升机高度、每巷道一台堆垛机、护栏罩住轨道等。
5. 不依赖 AI 也能操作：面板按钮和参数都能手动使用。

**非目标（本期不做）**
- 图纸语义识别（哪个块是什么设备），由 skill 和 AI 负责，插件只执行确认结果。
- DXF 设备块到资产的自动摆放（映射预设面板列在路线图里）。
- 渲染出图、材质美化。

## 3. 用户与场景

| 用户 | 场景 |
|---|---|
| 物流规划/方案工程师 | 拿到规划 DXF，快速出三维方案；图纸改版后重新对照 |
| 三维表现人员 | 在生成结果上调整货架层数、墙高，出效果图 |
| AI agent（通过 Blender MCP 或其他 Blender Python 接口连接） | 按 skill 流程识图、确认后，调用插件执行和验收 |

## 4. 设计原则：AI 与插件的分工

| 环节 | AI（skill） | 插件 |
|---|---|---|
| 识图 | 找楼层、判断块含义、排除副本和标注、定原点 | — |
| 确认 | 出清单和问题，收用户答复 | — |
| 配置 | 写 `project-config.json`（区域、原点、图层规则、参数） | 读配置 |
| 执行 | 调用操作器 | 节点组、转换、底图、墙体、高度对齐 |
| 验收 | 读摘要、判断是否符合用户意图 | 计数、规则检查、写报告 |

原则：**需要判断的交给 AI，确定性的交给插件；DXF 几何永远不经过 AI。**

## 5. 功能需求

### F1 注册节点组为资产 `wh.setup_nodes`
- 创建或重建两个节点组，并标记为资产，可以在资产浏览器里拖用：
  - `GN_XYZ阵列`：规则阵列；
  - `GN_点位实例`：不规则点位，一个对象里可混合多种资产。
- **验收：** 两个节点组都存在，且 `asset_data` 不为空。

### F2 转为 XYZ 阵列 `wh.to_xyz`
- **输入：** 选中对象、集合或对象名。支持集合实例空对象和点位对象。
- **处理：**
  1. 展开为"单元"（资产、中心、底面高度、朝向、单元尺寸）；
  2. 同一位置、等距叠放的单元合并成一柱（Z 数量）；
  3. 在局部坐标系里贪心分解出最大完整矩形：X 方向要连续等距，Y 方向合并的间距不超过 `max_dy`（默认 1.6m，避免跨巷道合并）；
  4. 分组挂到父级：`CLUSTER` 按占地连通（地堆区块），`LINE` 按同一排或列（货架），`NONE` 不分组。
- **修改器参数：** X/Y/Z 数量、X/Y/Z 间距、单元长 X / 深 Y / 高 Z（0 表示跟随间距）、离地高度。对象原点在第一个单元，数量加大时朝 +X/+Y/+Z 延伸。
- **安全：** 分解后单元总数必须等于源单元数，否则中止；替换前后实例数和包围盒一致才删除源对象，否则回滚。
- **验收：** 背靠背带缺口的两列货架 → 3 段、每段 Y=2、1 个父级；X 数量 4→5 时，实例数按比例变化。

### F3 转为点位对象 `wh.to_points`
- **输入：** 集合实例空对象。
- **分组：** `LINE` 按直线输送线分（同一 cy 且首尾相接的连成横线；其余按同一 cx 合成纵线；不超过 2 段的零散件并入最近的线），`ONE` 合成一个对象。
- **修改器参数：** 竖向节数、总高、排深覆盖、离地高度。
- **验收：** 本项目 183 个输送设备分成 25 条线，实例数一致。

### F4 高度对齐 `wh.align_heights`
- 自动识别货架顶（按资产类型规则）。
- 提升机顶 = 货架顶 + 余量（默认 1.0m，可在偏好里改）；堆垛机顶 = 货架顶。
- 支持空对象和点位对象中的对应点。
- **验收：** 提升机被压回原高后，执行即可恢复到 21.0m（货架 20m）。

### F5 验收报告 `wh.validate`
- 按类型、资产统计单元数：用每个资产的代表网格定位单元，不重复计数。
- **规则检查：**

| 规则 | 判定 |
|---|---|
| 提升机高于货架 | 高出范围在 0.3–2.0m（可配置） |
| 堆垛机约等于货架顶 | 偏差 ≤ 0.3m |
| 堆垛机与货架不干涉 | XY、Z 的包围盒不重叠 |
| 每巷道一台堆垛机 | 每条轨道上恰好 1 台 |
| 护栏罩住轨道端部 | 每条轨道至少一端被护栏平面覆盖 |

- **输出：** 文本块 `WH_验收报告`、`scene["wh_last_report"]`、可选 JSON；面板显示前 8 行。

### F6 导入平面底图 `wh.import_underlay`
- **输入：** 项目配置文件（必填）；替换图纸（可选，图纸出新版本且坐标不变时使用）。
- **处理：**
  - **区域递归筛选：** 整体在区域内的实体直接保留；跨区域的块递归拆开（例如绑定的整栋建筑外部参照）；区域外的跳过。
  - **快速筛选：** 用关键点加块定义缓存，不用精确包围盒。
  - **图层：** 外部参照图层名去前缀；块内 0 图层继承父级图层；默认跳过文字、标注、填充。
- **输出：** 集合 `DXF底图`，每个图层一个只有边线的网格对象；放在 z=−0.01、不可选中，颜色取 DXF 图层色。
- **缓存：** 按 DXF 大小和修改时间加配置签名，存成 `.npz`，命中时直接加载。
- **依赖：** 插件自带 ezdxf 和依赖的纯 Python wheel，不依赖系统 Python。
- **验收：** 与输送线模型对位误差 ≤ 0.3m；缓存重导入 < 5s。

### F7 对照模式 `wh.compare_mode`
- 切换为顶视正交视图，模型 X 光半透明（默认 0.4），底图按对象颜色显示，自动框选底图范围。
- 再点一次恢复原来的视角和着色方式。

### F8 一键挤出墙体 `wh.build_walls`
- **输入：** 项目配置文件的 `walls` 段；图层列表留空时按名字识别（WALL/墙、WIN/DOOR/门/窗、COLU/柱）。复用 F6 的缓存。
- **算法：**
  1. 在交点处打断线段、去重、剪掉悬挂边；
  2. 用半边结构提取平面面；互不相连的线网作为"洞"挂到包住它的最小面上（外墙内外线没连、房间里的独立柱都靠这一步处理）；
  3. 分类：墙段（厚度 2A/P ≤ 0.8m 且以墙线为主）、窗段、空间（面积 ≥ 3㎡）、柱（柱线为主且面积 ≤ 4㎡）；
  4. 在墙带的 T 形接头处横切，把长外墙切成段；
  5. 每段墙归入接触长度最长的空间，经其他墙段间接相连的沿相邻关系传递。
- **输出：**
  - 集合 `建筑_<楼层>`，下有 `墙体_<楼层>`：每个空间一个 `墙体_空间NN`，按面积降序编号，带空间面积属性；
  - `柱子_<楼层>`；
  - 可选 `空间地面`。
- **修改器 `墙体挤出`：** 高度、底标高，随时可改。
- **验收：** 本项目 53 个空间 → 54 个墙体对象（833 段墙，1 段未归属），158 根柱；墙高参数 7m 生效，改成 9m 也生效。

### F9 面板与偏好
- **N 面板「仓储布局」**，分组如下：
  - 平面底图：导入、对照、墙体；
  - 节点组；
  - 转换；
  - 调整；
  - 验收。
  选中阵列、点位或墙体对象时，显示「当前对象参数」。
- **偏好设置：** 资产库 .blend、提升机默认余量、验收余量范围、资产类型关键词规则。

## 6. 数据与配置：`project-config.json`

由 skill 在首次走查时生成，插件只读取。关键字段：

```json
{
  "dxf": "/…/图纸.dxf",
  "dxf_units": "mm",
  "origin_dxf_mm": [1660000, 110000],
  "underlay": {
    "name": "1F",
    "region_dxf": [1640000, 1900000, 95000, 205000],
    "exclude_layers": ["2F补货线", "0-标高", "PUB_TEXT", "GGSignatureLayer"],
    "include_text": false, "include_hatch": false, "flatten_m": 0.03, "z": -0.01
  },
  "walls": {
    "height": null, "column_height": null, "base_z": 0,
    "wall_layers": ["J-WALL", "J-WALL-彩板墙体", "J-石材幕墙", "J-轻质墙体"],
    "opening_layers": ["J-WINDOW", "J-WINDOW-防火", "WINDOW"],
    "column_layers": ["J-COLUMN", "砼柱"],
    "max_thickness": 0.8, "min_room_area": 3.0, "include_windows": true
  }
}
```

**资产类型规则**（偏好设置，按顺序匹配资产名）：

```
guard:护栏; rail:轨道; hoist:提升机; stacker:堆垛机; rack:货架; pallet:托盘; conveyor:链式机,辊筒,顶升,输送,外形检测,扫描
```

## 7. 程序接口（MCP 和脚本）

| 操作器 | 常用参数 |
|---|---|
| `wh.setup_nodes` | `rebuild` |
| `wh.to_xyz` | `collection` / `object_names`、`prefix`、`group_mode`、`merge_y`、`max_dy`、`keep_source` |
| `wh.to_points` | `collection` / `object_names`、`prefix`、`group_mode` |
| `wh.align_heights` | `margin`、`include_stackers` |
| `wh.validate` | `collection`、`json_path` |
| `wh.import_underlay` | `config_path`、`dxf_path`、`include_text` |
| `wh.compare_mode` | `xray_alpha` |
| `wh.build_walls` | `config_path`、`height`、`column_height` |

每次执行后，结果摘要写入 `scene["wh_last_result"]`（JSON），验收文本写入 `scene["wh_last_report"]`。

| 项 | 要求 | 本项目实测 |
|---|---|---|
| 底图首次导入 | < 60s（140MB DXF） | 40–50s（原方案 179s） |
| 底图缓存重导入 | < 5s | 0.13–0.16s |
| 区域筛选 | — | 2.3s（精确包围盒方案要 68s） |

## 9. 测试

- `tests/test_decompose.py`：纯 Python，5 项。背靠背带缺口、立库竖向叠放、L 形区块、不跨巷道合并、输送线分线。
- `tests/test_walls.py`：纯 Python。双房间合成建筑：外墙内外线不连、门封洞、独立柱。
- `tests/test_blender.py`：后台 Blender 回归，只读、不保存，覆盖 F1–F8，一共 18 项。
  运行方式：`WH_TEST_CONFIG=… Blender -b 项目.blend --python tests/test_blender.py`
- **当前状态：** 全部通过（v0.3.0）。

## 10. 已知限制

1. 底图线只在视口显示，渲染时看不到。
2. 窗段按实墙挤出，墙上没有开窗洞；门洞是空的。
3. 同一楼层只有一个墙高参数，分区墙高（比如高架立库区）需要手动改对应空间的墙体对象。
4. 资产类型靠资产名关键词识别；资产命名不规范时，要在偏好设置里改规则。
5. 墙体分空间依赖门扇和门弧把门洞封住；没有画门的开口，两侧会合并成一个空间。
6. 区域筛选取的是关键点范围，比精确包围盒略宽，本项目在边界处多出 10 个实体。
