# CAD2Scene 用户流程、生成门槛与恢复

这里定义代理执行与后续产品开发应遵守的流程。现有包是本地工具/模板，不是已上线的多用户服务。实现程度要按实际代码报告。

## 阶段与用户看到的内容

| 状态 | 用户看到什么 | 系统何时向前推进 |
|---|---|---|
| received / parsing | 文件名、当前步骤；可返回项目 | 文件可读、格式支持、范围可解析；坏文件给出具体原因 |
| classifying | 已解析图层/图块数量、正在检查映射 | 图层和型号匹配完成，问题汇总 |
| needs_input | 平面定位 + 待办卡片，显示问题类数和涉及对象数 | 当前生成范围的阻断项都解决 |
| ready | 已具备生成条件的范围及设备数量 | 按用户已授权的生成请求继续；无额外全表批准 |
| generating | 实际已处理/总数和当前步骤 | 资产载入、生成与基础校验完成 |
| available | 场景、设备详情、切层和修改入口 | 只有成功版本才能成为当前可用版本 |
| failed | 哪一步失败、保留了什么、如何重试 | 从失败步骤恢复；保留之前的确认和可用场景 |

解析前不知道总量时显示阶段，不伪造百分比。区分“图层分类完成”“型号匹配完成”“设备生成完成”；不把查表命中率称为识图准确率。等待用户、主动取消和处理失败不能混为一类。

## 生成门槛

每个设备分别维护 `mappingStatus` 与 `generationStatus`：

- mappingStatus：`unmatched / candidate / confirmed / conflict / not_applicable`。
- generationStatus：`blocked / ready / generated / failed / excluded / not_applicable`。
- blockers：问题代码列表，例如 `unknown_units`、`needs_mapping`、`needs_asset`、`needs_parameters`、`coordinate_conflict`、`duplicate_ambiguous`。

单设备 ready 的必要条件：当前来源和范围有效；设备角色明确；型号/代用有有效依据；资产实际可加载且来源通过核验；按型号定义的必填参数完整合法；单位、变换、锚点、楼层及去重通过检查。`已确认` 只代表答案已落库，不代表上述检查全通过。

整范围 ready：该范围所有应生成设备 ready，排除项有明确依据，建筑/楼板/公共坐标等共享依赖无阻断。路径和注记使用自身处理状态，不混入设备生成分母；涉及动画或楼板的必要非设备数据仍是共享依赖。

默认完整生成不绕过未决项。代理可继续无关分析、资产准备和确定区域的本地草稿；用户明确允许部分预览时，只输出 ready 子集并标记“部分预览、未生成数量/区域”，项目仍保留未决状态，不宣称完整可用。未知单位或全局坐标冲突影响全场，不能局部绕过。

## 核对过程

先充分读取图层、块属性、局部图形、模型资料及项目确认，不能把未分析的所有对象推给用户。核对页中确定内容作为灰色参照，待办高亮。每个问题包括：稳定编号、楼层/区域、原图局部或可定位轮廓、数量、缺失/冲突原因、推荐候选及差异、答案作用域。

同类合并依据是“规则集 + 规范图层 + 块定义/属性签名 + 问题类型 + 适用区域”，不能只按同层合并。例如同层 30 台同型充电桩可批量确认型号，但 1F 和 2F 的标高分别处理。批量操作显示会影响的对象数；用户只回答一组就只更新一组，不推断剩余答案。

选择模型与补录参数尽量在同一轮收集，不要求用户填写 SQL/JSON。可以接受对话回答或 HTML 导出答案。已有明确答案不重复问；无未决项不让用户逐条点确认。暂时跳过保留待办，不等于排除；“排除”必须有用户决定或可靠的非实物/范围证据。

错误文案说明对象、原因与下一步，如“G03 的 12 组货架缺少储位层数，请填写或沿用本项目已确认参数”。不要只显示解析失败、低置信度或内部堆栈。

本地 HTML 当前只有内存状态，明确提示导出保存；不能承诺自动保存。确认导入校验清单哈希与 ID 集合，过期答案先按来源差异核对，不能强行覆盖。详见 confirmation-contract.md。

## 版本与自然语言修改

场景数据是布局事实的唯一入口，CSV/HTML 是可导入的核对视图，渲染网格是派生结果。接收答案/修改时：

1. 保留原话、来源、作用域、基准版本及旧快照；定位稳定实例 ID。
2. 得到可检查的动作：对象集合、参数/位移、方向基准和单位。明确指令直接执行；“那排”“往前”无法唯一定位时只澄清该部分。
3. 在新草稿上应用并检查约束及受影响依赖。改变数量、模型、楼层或尺寸后同步更新相关派生信息。
4. 成功才切换当前版本并同步 CSV、HTML、配置及 placements；失败保留旧可用版本，报告未应用内容。重试使用同一任务/操作标识，避免重复加设备。
5. 回退恢复已保存快照并重建视图，不依赖 AI 用反向语句猜回原状态。

本地以 `_过程/versions/<revision>/` 保存输入、确认和场景快照，写入完成后再更新当前视图；服务化时使用事务/版本号检测过期写入。跨会话加载场景版本、项目约束、待办和相关操作，不依靠聊天历史作为唯一存储。此节是实现契约，不表示包内已提供事务后端或回退 UI。

## 展示与交付

新产品按照 PRD 提供上传、核对、生成、浏览、AI 修改；原“三建筑”模板仅是场景页的可复用实现。必要错误提示、选中设备名称、版本和待办入口不能被旧的“无文字”偏好删掉。拖拽编辑、选中对象传给助手、分享权限或动画以当前需求范围为准，不顺带扩张。

完成时优先给一个主入口、已完成范围和仍需处理的问题；SQL、CSV、PNG、配置为辅助链接，不每轮堆出所有过程文件。从任何阶段退出/重进都应能恢复已保存进度；未实现恢复功能时明确说明当前保存方式。
