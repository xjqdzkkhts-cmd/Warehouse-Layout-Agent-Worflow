# 识图、范围和溯源

## 从 CAD 到设备清单

使用 `ezdxf`；DWG 若无法直接解析，先用可用转换器取得 DXF，不能把改后缀当转换。先读取 `$INSUNITS`、模型空间与布局、图层、INSERT、TEXT/MTEXT 和范围，再用散点图找楼层/区域簇。工具调用示例：

```sh
python scripts/dxf_inventory.py stats drawing.dxf
python scripts/dxf_inventory.py texts drawing.dxf --region x0 x1 y0 y1
python scripts/dxf_inventory.py inserts drawing.dxf --region x0 x1 y0 y1 --out inserts.json
```

先按 [业务映射契约](business-mapping.md) 用生效图层精确查 JDL 字典，再在项目规则集内查块名。字典中的类别候选不能直接作为模型。

匿名动态块 `*U…` 用 `AcDbBlockRepBTag` 追原块名；原名有证据才用于查表，尺寸仍用当前求值块。实际名与原名命中不同映射时保留冲突，不静默选一个。结合图层、块内结构、文字、尺寸和相邻设备，不能只靠名字或包围盒猜类型。未知设备、已认出的缺资产设备、视觉代用件分开记，不能把“44 个未生成”全部描述成识图失败。

本用户要求未知设备和代用方案先确认再建模：提出原图局部、数量、候选类型与差异，不先把包围盒挤出成实体或套用普通提升机后再解释。用户若已批准“按图形重建、暂不指定工艺”，继续完成形态，分别记录外形确认与工艺未确认，不重复索要同一许可。智狼库的缩写、双位置和轨道误识别案例见 [智狼库搭配](zhilang-layout.md)。

工具的区域筛选以顶层实体中心/包围盒为近似，`render` 不是完整裁剪器。`土建`、绑定外参等巨型 INSERT 可能含多栋楼和图框，要递归展开至目标区域内几何；不能因为巨块中心在外而整栋漏掉。处理跨边界实体、bulge 弧、OCS、嵌套变换时回到 DXF 原始几何验证。

检查整体平移的重复主图、图框外副本、混入的上层图层；组合块不能父子重复计数。巷道两端的堆垛机可能是两个极限位，需要图纸依据确认实物数。立库尾部小块也可能是护栏、检修设施，不能见矩形就当托盘。LED/BCR/标高等注记通常不算独立设备。

## 坐标与高度

INSERT 变换顺序为 `T(insert) · R · S · T(-blockBase)`，嵌套从外到内累乘。**插入点不等于几何中心**；有些块内部偏移很大。保留镜像符号，负缩放不能仅取绝对值后丢失功能朝向。对非默认 OCS 先转 WCS。

记录唯一 CAD 原点、单位比例和整体平面旋转。常用右手系映射 CAD `(x,y,z)` 到网页 `(x,z,-y)`，但以资产实际轴约定为准。不同楼层在 CAD 中横向排版时需要各自平面基准，不能直接把纸面偏移当真实楼栋间距。布局、墙体、底图和动画路径必须用同一变换链。

分开存储 `buildingFloor`、`rackLevels`、`rackHeight`、`conveyorSurfaceHeight`。从容量标注可交叉核对 `组数 × 每层托数 × 储位层数`；容量核对不能证明设备位置和语义都正确。平面图没给出的高度保留未知，使用获准的展示参数并注明依据，不能从外框长度推出总高。

## 审阅产物与数据契约

沿用原 skill 的 `输出/识图确认/`，存设备 CSV、编号预览 PNG、摘要、`project-config.json` 和 `placements.json`；解析中间结果放 `_过程/` 并复用。已确认内容不用强迫用户再填表。

每项至少记录：稳定 `id`、`sourceHandle`、嵌套路径、图层、动态原名、所选区域/楼层、变换、资产 ID、判定依据、状态及代用说明。资产到多零件的 1:N 或父子合并的 N:1 映射显式记录，避免把网格数当设备数。保留原文件和资产哈希以复现结果。

底图应包含可对照的设备轮廓和建筑轮廓；仅有墙柱时明确写“建筑底图”，不能据此宣称设备识别准确。原始图纸抽样是独立基准，不能只用同一个识图脚本生成的清单互相验证“100%准确”。诊断清单允许编号文字，原三建筑展示界面不加常驻设备标签；CAD2Scene 仍显示必要的选中名称、待办和错误提示。
