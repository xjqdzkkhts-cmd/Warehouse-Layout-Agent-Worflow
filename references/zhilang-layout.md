# 智狼库搭配、识图与动作

适用于已确认使用智狼设备的料箱库与货到人工作站。依据用户提供的典型智狼库参考图、独立 GLB 模型库和园区 CAD 项目的确认记录。参考图用于判断组成与连接关系；尺寸、数量、层数、工艺流向以本项目 CAD 和用户确认优先。

## 设备搭配与资产选择

| 部分 | 资产与建模方式 | 必须保留的关系 |
|---|---|---|
| 料箱货架 | 按 CAD 箱位、列数、层数重组；包内 `shelving` 仅作构件参考，须按 [货架结构规则](rack-structure.md) 重组，禁止整侧框拉高或单排拉成双排 | 架体、承载层、料箱分开；层数不是整架拉高得到 |
| 料箱 | `bin` | 放在真实支撑面上，开口与交接口朝向正确；静态库位箱与流转箱分开 |
| 地面智狼小车 | `agv-zhilang` | 轮子接地；料箱跟随 cargo 接口；按通道行驶、对位、取放 |
| 智狼大车 | `zhilang-large`，按巷道轨迹和货架高度派生 | 钢架沿平行货架的轨道移动，升降狼在钢架内上下运动 |
| 智狼入库线 | **`conveyor-zhilang`** | **红色机架是该设备标配**；保留实际长边机架、端部交接结构、灰色支腿和导向构件 |
| 其他辊筒工作段 | CAD 确认是辊筒线时使用 `roller-conveyor` 或按实际零件组装 | 辊筒轴垂直运输方向，节距与直径保持合理，不把整段滚筒拉长 |
| 工作台、门、护栏、充电位 | 库内有 `workbench`、`packing-table`、`safety-guard`、`charger-zhilang` 等候选 | 先比对结构与接口；护栏不等于门，工作台不等于所有矩形设备 |

用户已明确：红色结构对应库内的标准「智狼入库线」，不是仅在某个项目中选择红色的普通输送机。优先加载独立库中的原 GLB，再按 CAD 校准或派生；**不能以“普通输送机整体染红”代替该设备，也不能把所有红色辊筒工作段都自动认成该型号**。机架颜色本身不证明承载面、移载结构与用途相同。

匹配时查看模型实际几何和 spec，不能只看中文名称或外包围盒。宽度、长度、高度需改变时保留支腿、护栏、交接端等结构比例；连续承载段延长或增加模块。只有 CAD/已确认参考确有双层回流线、侧支线、屏幕或人员工位时才补这些部件，不照搬典型图的全部细节。

## 先辨认，再确认未知项

对 CAD 缩写，联合查看块内线条、平行长边、重复辊筒、支线、门扇开启弧和相邻小车/料箱。外包围盒仅用于定位、碰撞与粗筛，不能直接挤出成灰色柜体后当作已识别设备。

本用户要求在未知设备建模、缺资产代用前提出具体候选并确认。一次确认可覆盖同类块；用户已授权“按图形重建、暂不指定工艺”时，保留 CAD 的实际外形并继续施工，不再重复询问同一外形许可。记录 `shapeStatus` 与 `processStatus`，不能用外形批准冒充工艺批准。

下面是本次园区图纸的案例，**不是行业缩写词典，也不是后续 CAD 的自动映射表**：

| 图块 | 本项目形态依据 | 参考图推测与边界 |
|---|---|---|
| KXF（2 处） | **用户已确认：输送线配上料箱** | 同时生成输送设备和其承载的料箱；入库/回流用途、方向及满空箱状态仍未指定 |
| DYF（2 处） | 辊筒主段与侧向交接段 | 可关联工作站输送交接；具体输入、输出和分流用途未定 |
| ZFS（3 处） | 台面和支架 | 拣选/复核工作台是推测，不把名称扩写成已确认工艺 |
| JL1000Y（4 处） | 门柱、门扇、开启扫掠弧 | 已获准按门形重建；开启弧保留为通行范围，不生成实体墙或方箱 |

“红色机架是智狼入库线标配”已确认；“某个未确认的 CAD 缩写必定是该入库线”仍需证据。这两件事分别记录。

### KXF：输送线与料箱一起建

本项目 KXF 类型已由用户确认，不再作为未知柜体或仅有空机架处理。仅延续同一项目且图块定义、结构和确认作用域未变时沿用；新项目即使同名同形，也先作为候选并核对项目证据：输送线是设备，线上料箱是它承载的货物；其他项目只出现同名缩写但结构不同，仍先核对。

从 `bin` GLB 取料箱，沿真实输送轴布置到有效承载范围。箱底对齐输送面而非机架护栏最高点；保留箱间距、端部净空和合理宽度，不悬空、不穿护栏。CAD 未标箱数时按展示需求布置并记录为演示数量；本次每段 5 箱不是容量或通用标准。没有证据不自动填入箱内货物。

线上料箱使用独立货物实例和 `ownerId/supportId`，跟随仓库与货物开关；不能烘焙进设备网格导致关货物后仍残留。获准启用输送动画时，再按端口与状态机推进、交接；出现料箱不代表已确认工艺流向或已实现出入库。

## 大车数量与运动关系

本次 `飞梯俯视002` 的 26 个图形，经用户确认是 **13 台智狼大车、每台两个位置**。`M-大车` 细长线表示轨道，不额外生成车辆。新图必须重新判断；不能机械地把所有成对符号数量除以二，也不能把所有“飞梯”都映射为同一型号。

去重方法：按巷道、姿态、横向中心线和轨道对应关系聚类，确认两端是设备中心位置还是轨道端点；保留两处 `sourceHandle/nestedPath`，合成一个 `physicalId`。轨道有自己的 role 并关联所属设备；设备数不包含轨道。若含义不明，先询问“一巷两车还是同车两个位置”。

推荐层级：

```text
行走根（沿实际轨道轴）
└─ 钢架
   └─ 升降狼（局部竖向）
      └─ 载货接口
         └─ 料箱
```

不能给整机做垂直货架的往返，不能让升降狼脱离行走钢架。源 GLB 很矮而货架很高时，按实际部件延长立柱和导向件；保留底座、顶梁、承载器高度，重算行程与限位。整台模型统一竖向拉伸会把承载器拉成数米高的大块，禁止以这种方式适配。

检查整段移动和上下极限位：大车扫掠包络不碰架，升降狼不穿顶梁/底座，载货箱不脱离支撑面。扫掠包络应覆盖设备与载货，而非只检查轨道中心线。本项目 18 层、约 10.8 m 为已批准展示参数，13 台为已确认数量；这些数值不默认继承到新项目。

## 输送连接、接地与物流

按实物的运输轴、承载面高度和端部位置连接，不靠整体包围盒相贴。必要时对 GLB 作局部 90° 轴修正，同时保留 CAD 外轮廓；镜像/旋转后的端口一起变换。脚底接建筑楼板或地面，箱底接滚筒/平台，三者高度不能混用。

接口至少记录位置、外法向、有效宽度、承载高度与设备归属；工艺未确认时命名 `endA/endB/side` 等几何接口，待确认后再分配 infeed/outfeed。红色机架和灰色护栏都不是承载面的证据；检查实际承载结构及交接缺口。两段位置或高度不符时先定位尺寸/轴向错误，不用隐藏箱子或无依据补一块平板掩盖。

设备搭配不自动等于完整工艺。若用户授权安排演示，可按现有接口编排“货架/大车 ↔ 地面小车 ↔ 入库线/工作站”，逐项确认设备是否支持这种交接；实际入出库方向、满空箱路径及作业步骤仍由图纸或用户指定。取货、载货、放货用状态机和单一货物所有权；交接需位置、高度、空闲和就绪同时满足。

## 小车轨迹与交互

小车路径绕开架体、支腿、设备和墙，按车体及载货包络膨胀障碍。直角路线采用“到点减速/停稳 → 最短角度转向 → 再前进”，或者经净空验证的转弯弧；不能车头尚未转正就横向滑动。格网预约至少考虑起点和终点占位，不以一次无碰撞截图宣称工程级交通验证。

使用固定仿真步长或正确的 dt，统一暂停和倍速；验证暂停时车、承载器、货物均冻结，30/60 FPS 的运动结果一致。初始 CAD 位置若需调整到可通行处，保留原位、实际位及偏移原因。

本用户要求点击小车或车载箱即跟随：拾取结果沿 ownerId 找实际 AGV，实例化货物也保留归属；相机随车平移，人工拖动退出跟随，切换仓库清除旧目标。总览点击仓库本体或建筑名称进入该库，允许隐藏遮挡外墙。交互遵循原黑白前端；建筑名称开关是已确认的标签例外，不因此增加设备标注。

## 交付时验证什么

- 顶视对照 CAD：货架、轨道、大车、工作站轮廓与朝向；设备数按物理 ID 统计，不算双位置或轨道。
- 近景对照标准 GLB：智狼入库线结构与红色机架，支腿落地、箱体有承载面、端口连续；其他辊筒段功能轴正确。
- 动态检查：整段大车行程及升降极限、小车拐弯与载货、暂停倍速、点击跟随和退出。
- 容量有冲突时保留未确认状态。本项目 26 处 3/4 箱位重叠尚未解决；模型满货不证明容量正确。

本包已有上述标准智狼入库线、大小车与料箱 GLB；不包含园区项目专用 KXF/DYF/JL1000Y/ZFS 派生模型、高架大车派生模型、项目 CAD 或外部高精度库。规则指导如何匹配与派生，不能宣称这些项目代码已随安装包交付，也不能宣称已接入 WMS/WCS 或完整仿真。
