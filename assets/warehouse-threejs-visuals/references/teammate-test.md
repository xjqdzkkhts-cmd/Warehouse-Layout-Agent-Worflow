# 同事测试说明

## 这次要验证什么

使用另一个真实仓储场景，验证本包的同一套 Three.js 材质、光影和画质策略能否迁移。
不是复刻发送者的仓库布局，也不是测试 CAD 自动搭建或 UE 工程。

请准备：

- 一个自包含的 GLB，先用可完整检查的小场景。
- 一个已知尺寸和地面标高。
- 说明模型有没有旧地坪、完整建筑，以及哪些对象允许隐藏或替换。
- 电脑的显卡、内存、操作系统和浏览器。
- 有条件时提供材质角色说明、期望镜头和已确认通道。

## 使用方式

将整个 `warehouse-threejs-visuals` 文件夹交给支持本地技能的助手，
按所用工具的技能安装方式安装；也可直接让助手先读取该目录的 `SKILL.md`。
不要只发送这一页或只复制 `SKILL.md`，运行模板、脚本、贴图和参考图都在同一个包里。

可直接给助手这段任务：

> 请使用 warehouse-threejs-visuals 技能包，把我提供的 GLB 接入其写实预览。
> 先核对单位、已知尺寸、地面和建筑情况，再创建独立输出，不修改原模型。
> 复用包内材质和渲染模板，不重新凭感觉实现另一套效果。
> 按技能的测试约定检查预设、自定义、静止与移动画面，并记录哪些地方只改配置、
> 哪些地方必须修改代码，以及当前电脑的实际表现。未验证项请明确说明。

如果所用工具支持显式技能名，可在任务中写 `$warehouse-threejs-visuals`。

## 最快的运行检查

Node.js 20 或更高版本可直接复制并运行预编译模板，无需先安装源码依赖：

```sh
node scripts/create-preview.mjs --out ./smoke-preview
```

进入 `smoke-preview` 后：

```sh
node scripts/start-server.mjs
```

终端会给出只供本机访问的地址，端口占用时另选端口。
首次展示两个合成样例，用于确认包内运行资源完整，不代表真实项目验证。
真实模型的导入命令、地坪处理和配置说明见 [场景接入约定](scene-contract.md)。

源码修改、自动测试需要安装 `package.json` 中的锁定依赖。
支持 npm 或 pnpm；环境允许时再下载安装，不要求覆盖现有项目或全局运行库。

## 请交回

新场景配置、三张主要截图、一段移动记录、测试报告和硬件信息。
另外说明“只改了配置，还是修改了公共代码”。
如果视觉未达到参考水平，请指出具体材料、视角或操作，不仅给出“像不像”的总体评价。

真实模型未提供、依赖或浏览器不可用时，不应把合成样例通过写成真实项目通过。
