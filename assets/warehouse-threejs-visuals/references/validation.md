# 跨场景测试与验收

本包已有检查的范围见 [封装验证记录](package-validation.md)，不要把它当作新项目的验收结果。

## 测试是否成立

这是一项可行的迁移验证：把另一个场景交给另一位操作者，
只使用技能包和明确的输入资料，检查能否重现同一套视觉能力。
不同设备、颜色、布局和建筑不会产生相同图片，因此不能做逐像素“同等画质”判断。

先用包内合成样例确认运行模板与资源完整，再测试同事的新 GLB。
人工评价与自动检查分别记录，不用颜色差值或非空像素证明主观质量提升。

## 必要检查

1. **输入正确**：源文件 SHA256、单位、轴向、已知尺寸、源面数口径、实例与外部资源。
2. **几何未误改**：设备位置、尺寸、数量、关键连接关系；原文件保持完整。
3. **地面唯一**：指定旧地坪确实隐藏，平面反射只是展示辅助层，不出现共面实体争抢。
4. **材料可信**：金属、涂层、塑料、纸箱、橡胶有区别，品牌标识和已有好材质未被破坏。
5. **光影稳定**：接触处有层次，AO 不大范围发黑，地面不整片像水，灯具不过曝成大白块。
6. **交互正确**：高/中/低与单项一致；自定义可恢复；场景显隐和镜头不被预设覆盖。
7. **移动正确**：连续旋转、平移、缩放和漫游都检查，停止后重新累积；不能只看静止截图。
8. **尺寸与缓存**：切换画质及窗口大小后实际 AO 目标尺寸正确，旧帧不残留。

## 建议保留的证据

- 同一新场景的总览、设备近景、地面近景。
- 固定镜头下的原始材质、高画质、AO 关闭、程序化细节关闭对照。
- 至少一段连续移动记录；没有录屏能力时保留连续帧并说明局限。
- 桌面与手机尺寸截图。手机尺寸模拟不是实际手机性能测试。
- 实际浏览器/操作系统/GPU/内存、画布分辨率和最终参数。
- 完成、未完成和需要人工修正的内容，以及为适配新场景改了哪些配置或代码。

## 自动检查

在输出预览目录安装开发依赖后：

```sh
npm test
node scripts/start-server.mjs
npm run verify -- --project scene-test
```

检查器使用 Playwright。若没有其浏览器，按所在环境安装，或用 `CHROME_PATH`
指定本机 Chrome 可执行文件。共享运行库可通过 `WORKSPACE_NODE_MODULES` 指向已有
Node 包目录；不要把别人的机器绝对路径写回技能或项目。

检查结果在 `reports/<project-id>/`。`success: true` 表示自动项目通过，
`qualityJudgment: requires human review` 提醒继续看图，不把自动结果当美术验收。
如果浏览器或权限不可用，保留输出并列明缺失检查，不改用伪造截图或跳过后宣称通过。

## 性能口径

`renderMs` 是 JavaScript 提交耗时，不是 GPU 完成时间。
静止时 TAA/AO 已缓存，提交计数很低是正常现象，不能据此报告持续 FPS。
源累计面数、唯一网格数、当前相机绘制面数和多通道重复绘制成本分别讨论。

普通办公电脑要单独记录加载时间、持续漫游体验、峰值内存及长时间稳定性。
如设置 30 FPS 等验收目标，必须标成项目目标，再用实际帧时间验证，不能从模板推算。
本包没有对 1.8 亿面、完整园区或 ThinkPad 产品线作性能保证。

## 建议交回的结论

采用短报告，包含：

- 输入模型、已知尺寸、硬件与浏览器。
- 使用了哪些材质角色、建筑假设和画质设置。
- 哪些效果达到参考水平，哪些差异来自模型、资料、硬件或实现。
- 是否仅改配置；如修改了公共代码，列出原因和复现方式。
- 主要截图、移动记录、自动检查报告及未验证项。

“达到现有同等效果”的建议通过条件是：几何正确、主要材料可辨、光影可信、
没有移动回归、预设行为正确，并在目标机器上满足已约定的交互要求。
